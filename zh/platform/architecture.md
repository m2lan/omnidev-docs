# 架构设计

## 系统概述

OmniDev 平台采用微服务架构，主要组件如下：

```
┌─────────────────────────────────────────────────┐
│                   前端                           │
│              (Next.js / React)                   │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────┐
│                  网关                            │
│      (Go / Gin) + knowledge-engine (库)          │
└──┬──────────┬──────────┬──────────┬─────────────┘
   │          │          │          │
   ▼          ▼          ▼          ▼
┌──────┐ ┌──────┐ ┌────────┐ ┌──────────┐
│ 聊天 │ │ 认证 │ │ 知识引擎 │ │ 工作流   │
│ 服务 │ │ 服务 │ │        │ │ (Temporal)│
└──────┘ └──────┘ └────────┘ └──────────┘
      │                ▲
      └── MCP / HTTP ──┘
```

## 核心组件

### 网关
- HTTP API 服务器
- 请求路由和中间件
- 认证和授权
- 直接 import 共享的 `knowledge-engine` 模块，为 `/api/v1/knowledge` 和 RAG 上下文提供能力，
  不再维护第二份 RAG 实现

### 聊天服务
- LLM 提供商集成
- 会话管理
- 流式响应
- 调用外部 MCP 服务（例如 `knowledge-engine` 的 `POST /mcp`）并执行工具调用轮次

### 知识引擎
- 基于 Tika 的文档解析
- 向量生成与 pgvector 存储
- 向量 + 全文混合检索
- 同时以 REST API 和 MCP 服务（HTTP / stdio）暴露

### 工作流引擎
- 可视化工作流构建器
- 通过 Temporal 进行任务编排
- 事件驱动执行

## 数据流

1. 用户通过前端发送请求
2. 网关进行认证并路由到相应服务
3. 服务处理请求并返回响应
4. 通过 WebSocket 或 SSE 进行实时更新
